# تهيئة أدوات الدورة وربط التكاملات

هذا **دليل التنفيذ الخاص بك أنت (Claude)** — المتدرّب لا يقرأه. أمّا الخطوات التي يراها المتدرّب فهي في القسم **7.10** من ملف خارطة الطريق (`bootcamp_roadmap_and_curriculum.md`).

## 0. القاعدة الحاكمة

**أنت تنفّذ كل ما يمكن تنفيذه من سطر الأوامر؛ ولا يبقى للمتدرّب إلا ما يحتاج هويّته الشخصية** (إنشاء حساب، نسخ مفتاح، تأكيد OAuth في المتصفّح).

قبل أي أمر: **اكتشف نظام التشغيل** واختر الصيغة المناسبة له — لا تفترض ويندوز ولا macOS. الفروق العملية:

| | Windows (PowerShell) | macOS / Linux (bash) |
|---|---|---|
| اقتباس القيمة التي فيها مسافات | `"..."` | `"..."` |
| متغيّرات البيئة | `$env:NAME` | `$NAME` |
| المسارات | `\` أو `/` | `/` |

## 1. حدود قدرتك — اقرأها قبل أن تَعِد المتدرّب بشيء

| العمل | مَن ينفّذه |
|---|---|
| `claude mcp add …` | **أنت** (عبر سطر الأوامر) |
| `claude mcp list` للتحقّق | **أنت** |
| كتابة المفاتيح في `.env` | **أنت** |
| إنشاء الحسابات ونسخ المفاتيح | المتدرّب |
| تثبيت Node.js على جهازه | المتدرّب — **والتحقّق عليك أنت** |
| `/mcp` ← **Authenticate** ← الموافقة في المتصفّح | **المتدرّب وحده** — تدفّق تفاعلي يحتاج هويّته، ولا تستطيع أنت تنفيذه |
| `claude plugin install …` (تثبيت chrome-devtools) | **المتدرّب وحده** — الأمر يفتح شاشة تأكيد تفاعلية، ولا تقدر أنت تتعامل معها من داخل المحادثة (لا علاقة بهويّته هنا، بل بطبيعة الأمر نفسه) |

> **تنبيه لازم أن تقوله للمتدرّب:** الخادم المضاف حديثًا **لا يعمل في الجلسة الحالية**؛ لا بدّ من **إعادة تشغيل Claude Code** أو إعادة الاتصال عبر `/mcp`. إن لم تقل هذا، سيظنّ المتدرّب أن الربط فشل.

## 2. هويّة Git — البند 3، وما ليست عليه

**ما يفعله المتدرّب:** يثبّت Git، ثم يضبط `user.name` و`user.email` مرّة واحدة.

**ما تقوله له عن البريد:** البريد يدخل في **كل حفظ ويبقى في تاريخ المستودع للأبد**. فاعرض عليه البريد البديل من GitHub قبل أن يعطيك بريده الحقيقي: **Settings ← Emails ← «Keep my email addresses private»** يمنحه عنوانًا بصيغة `ID+username@users.noreply.github.com`، وهو **مرتبط بحسابه فعليًّا** فتُنسب مساهماته إليه بصورته واسمه كالمعتاد. **اقترحه ولا تفرضه** — مستودعات الدورة خاصّة، فهذا تحسين لا شرط. ومعه خيار مفيد: **«Block command line pushes that expose my email»**.

> ⚠ **لا تخلط بين الهويّة والتوثيق.** `user.name`/`user.email` **بطاقة اسم** تُختم على الحفظ، وGit لا يتحقّق منها إطلاقًا. أمّا **تسجيل الدخول إلى GitHub** فيحدث أوّل مرّة يُرفع فيها المشروع (المهمة 14.1) عبر مدير بيانات الاعتماد ومتصفّح المتدرّب — تفاصيله في مهارة `building-features`. لا تَعِد المتدرّب بأن الرفع سيمرّ لمجرّد أن الهويّة مضبوطة.

## 3. Node.js — البند 6، وتثبيته على المتدرّب

**لماذا؟** هو ما يشغّل تطبيقه فعلًا. بدونه يفشل `npm install` وتفشل `npm run dev` — وهذا أوّل ما يتعثّر عنده أوّل تشغيل في المهمة 14.1.

**ما يفعله المتدرّب:** ينزّل نسخة **LTS** من <https://nodejs.org/en/download> ويشغّل المثبّت بإعداداته الافتراضية. نبّهه إلى شاشة **Tools for Native Modules**: يتركها **بلا تفعيل** (وهو الوضع الافتراضي) — تفعيلها يبدأ تنزيل أدوات بناء طويلة لا نحتاجها في الدورة.

**ما تفعله أنت:**

- **تحقّق بنفسك لا بتأكيده الشفهي:** `node -v` ثم `npm -v` — في موجّه أوامر **جديد**، فالنوافذ المفتوحة قبل التثبيت لا ترى البرنامج.
- إن جاء «الأمر غير معروف» رغم تثبيت ناجح، فالسبب غالبًا نافذة قديمة؛ اطلب منه واحدة جديدة، ثم إعادة تشغيل الجهاز إن استمرّ.
- **لا تبدأ تهيئة التطبيق ولا تشغّل شيئًا قبل أن ينجح الفحص.** البدء ثم التعثّر في منتصف الطريق يربكه أكثر من انتظار دقيقتين.

## 4. chrome-devtools

**لماذا؟** يتيح لك فتح موقع المتدرّب في متصفّح حقيقي والنقر فيه وتعبئة نماذجه وقراءة أخطائه — فتختبر كل وظيفة تبنيها بنفسك بدل الاكتفاء بـ«انتهيت». **يُربط الآن** (لا في المهمة 14.2 كما في نسخة سابقة من هذا الدليل) لأنه أبسط الثلاثة ولا سبب لتأجيله.

**استثناء وحيد عن القاعدة الحاكمة (§0):** هذا التكامل الوحيد الذي **يكتب أوامره المتدرّب لا أنت** — ليس لأنه يحتاج هويّته، بل لأن أمر `claude plugin install` يفتح **شاشة تأكيد تفاعلية** داخل سطر الأوامر نفسه، ولا تقدر أنت تتعامل مع شاشة كهذي من داخل محادثتك. أخبره بهذا صراحةً حتى لا يظنّ أنك تحيله إلى شغل هو غالبًا شغلك.

**ما يفعله المتدرّب** — أربعة أسطر في نافذة أوامر جديدة (منفصلة عن محادثتك):

```
claude plugin marketplace list
```
تحقّق من وجود `claude-plugins-official` في القائمة.

```
claude plugin install chrome-devtools-mcp@claude-plugins-official
```
انتظر نحو 15 ثانية حتى تظهر `Successfully installed plugin: chrome-devtools-mcp@claude-plugins-official (scope: user)`.

```
claude mcp list
```
ابحث عن `chrome-devtools … ✔ Connected`، ثم يغلق النافذة.

> **إن ظهرت رسالة `Run /reload-plugins to activate`:** نفّذها أنت داخل المحادثة، أو اطلب منه إعادة تشغيل Antigravity — أيّهما أسرع.

## 5. context7

**لماذا؟** يجلب توثيق المكتبات والأطر المحدّث فتكتب كودًا مطابقًا لأحدث الإصدارات. **يُربط قبل أي عمل برمجي** — أي قبل تهيئة التطبيق في اليوم الأول.

**ما يفعله المتدرّب:** ينشئ حسابًا على <https://context7.com/> ← لوحة التحكّم ← **API Keys** ← ينشئ مفتاحًا وينسخه (يبدأ بـ `ctx7sk-`) ← **يلصقه لك في المحادثة**.

**ما تفعله أنت** بعد أن يعطيك المفتاح:

```
claude mcp add --scope user --header "Authorization: Bearer <KEY>" --transport http context7 https://mcp.context7.com/mcp
```

- `--scope user` مقصود: التوثيق المحدّث نافع في كل مشاريع المتدرّب لا في مشروع الدورة وحده.
- على PowerShell أبقِ قيمة `--header` بين علامتَي اقتباس مزدوجتين كما هي أعلاه.
- الاتصال البعيد يعمل **بلا مفتاح** لكن بحدّ استخدام منخفض (anonymous rate limit)؛ ولهذا نستخدم مفتاحًا.

**بعدها:** أخبر المتدرّب أن يعيد تشغيل Claude Code، ثم تحقّق أنت بـ `claude mcp list` من ظهور `context7 … ✔ Connected`.

## 6. إنشاء مشروع Supabase — **قبل** ربط الـMCP

**الحسابات متطلّب مسبق** (GitHub · Supabase · منصّة النشر · بريد فعّال) يجهّزها المتدرّب قبل الدورة. أمّا **مشروع** Supabase فيُنشأ الآن، **ولا بدّ منه قبل الخطوة التالية** لأن الـMCP يحتاج مشروعًا يشير إليه.

> **قبل هذه الخطوة يجب أن تكون بيدك نبذة المتدرّب عن فكرته** (`CLAUDE.md` القسم أ.2.1). هنا تُستعمل أوّل مرّة: **أنت تقترح اسم المشروع مشتقًّا منها**، فلا يخترعه هو ولا تعطيه اسمًا عامًّا. وإن لم تكن أخذتها بعد، اطلبها الآن قبل أن تكمل.

وجّه المتدرّب في <https://supabase.com/dashboard> ← **New project**:

| الحقل | ما تقوله له |
|---|---|
| **Organization** | مؤسّسته الشخصية (تُنشأ تلقائيًّا مع الحساب) |
| **Project name** | **اقترحه أنت** من نبذته — حروف صغيرة وشرطات |
| **Database password** | ⚠ **انسخها واحفظها الآن في مكان آمن** — لا تُعرض مرّة أخرى، واستعادتها تتطلّب إعادة تعيين |
| **Region** | الأقرب جغرافيًّا لمستخدميه (يقلّل البطء) |
| **Plan** | **Free** يكفي للدورة بالكامل |

التجهيز يستغرق دقيقة أو دقيقتين. بعده تجد بيانات الاتصال في **Project Settings**: نصّ الاتصال بقاعدة البيانات (connection string)، ورابط الـAPI ومفاتيحه (publishable keys).

> **ولا تطلب منه نسخ هذه البيانات.** بعد ربط الـMCP (القسم 6 أدناه) تجلبها أنت مباشرةً بأداتَي **`get_project_url`** و**`get_publishable_keys`**، وتكتبها بنفسك في `.env` عند التهيئة في المهمة 14.1. لا تطلب منه لصق شيء إلا إن تعذّر الوصول فعلًا. وتأكّد أن `.env` في `.gitignore`.

> **لماذا Supabase؟** تعطي قاعدة بيانات **ونظام تسجيل دخول جاهزًا** معًا، بلا Docker وبلا تثبيت محلّي، وتعمل نفسها في التطوير وبعد النشر — فلا فرق بين البيئتين.

## 7. Supabase MCP

**لماذا؟** يتيح لك إنشاء الجداول وتشغيل التهيئة وقراءة سجلّات قاعدة البيانات مباشرةً — فلا يحتاج المتدرّب أن يفتح لوحة Supabase ويكتب SQL بنفسه.

**ما يفعله المتدرّب في لوحة Supabase:** يفتح مشروعه ← زر **Connect** ← تبويب **MCP** ← يختار العميل **Claude Code** ← يترك **read-only** **مُطفأً** (لأنك ستُنشئ الجداول نيابةً عنه) ← يترك مجموعة **Storage** مُطفأة (لا نحتاجها) ← ينسخ معرّف المشروع (project ref) إن ظهر له.

**ما تفعله أنت:**

```
claude mcp add --scope project --transport http supabase "https://mcp.supabase.com/mcp"
```

- `--scope project` مقصود: قاعدة البيانات تخصّ هذا المشروع وحده، فلا تُسرّبها إلى بقيّة مشاريع المتدرّب.
- إن أعطاك المتدرّب معرّف المشروع، اربطه بمشروعه تحديدًا: `"https://mcp.supabase.com/mcp?project_ref=<REF>"` — وهذا أفضل، إذ يمنع وصولك إلى بقيّة مشاريعه.
- لا يحتاج هذا التكامل مفتاحًا شخصيًّا (Personal Access Token)؛ التوثيق يتمّ عبر OAuth في المتصفّح.

**ثم — خطوة المتدرّب وحده:** يشغّل `/mcp` ← يختار `supabase` ← **Authenticate** ← يوافق في المتصفّح. اشرح له ما يمنحه من صلاحيات قبل أن يوافق.

**التحقّق:** اطلب منه أن يسألك عن جداول قاعدته، ونفّذ الطلب فعلًا لتثبت أن الربط يعمل.

## 8. التكامل المؤجَّل — لا تربطه في اليوم الأول

نوزّع مجهود التهيئة على الأيام بدل تكديسه في اليوم الأول: **Vercel MCP** وحده يُربط لاحقًا، في القسم **16.2** مع النشر (تفاصيله في مهارة `deploying`) — أمّا chrome-devtools وcontext7 وSupabase MCP فتُربط الثلاثة اليوم (§4–§7 أعلاه).

إن طلب المتدرّب ربط Vercel MCP مبكرًا فلا مانع، لكن نبّهه أن كل تكامل مربوط **يزيد حجم كل رسالة** ويستهلك رصيده (القسم 7.6).

## 9. أمان المفاتيح — قاعدة صارمة

عندما يلصق المتدرّب مفتاحًا في المحادثة:

- استخدمه في الأمر أو اكتبه في `.env` **فقط**.
- **لا تُعِد كتابته في ردّك**، ولا تضعه في `conversation_history.md` ولا في `PRODUCT.md`. عند توثيق الخطوة في سجلّ المحادثة اكتب `<تم استلام المفتاح>` بدل قيمته.
- تأكّد أن `.env` مذكور في `.gitignore` قبل أول رفع.
