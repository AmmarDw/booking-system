# تهيئة أدوات الدورة وربط التكاملات

هذا **دليل التنفيذ الخاص بك أنت (Claude)** — المتدرّب لا يقرأه. أمّا الخطوات التي يراها المتدرّب فهي في القسم **7.10** من ملف خارطة الطريق (`bootcamp_roadmap_and_curriculum.md`).

## 0. القاعدة الحاكمة

**أنت تنفّذ كل ما يمكن تنفيذه من سطر الأوامر؛ ولا يبقى للمتدرّب إلا ما يحتاج هويّته الشخصية** (إنشاء حساب، نسخ مفتاح، تأكيد OAuth في المتصفّح).

قبل أي أمر: **اكتشف نظام التشغيل** واختر الصيغة المناسبة له — لا تفترض ويندوز ولا macOS. الفروق العملية:

| | Windows (PowerShell) | macOS / Linux (bash) |
|---|---|---|
| اقتباس القيمة التي فيها مسافات | `"..."` | `"..."` |
| متغيّرات البيئة | `$env:NAME` | `$NAME` |
| المسارات | `\` أو `/` | `/` |

## 1. حدود قدرتك — اقرأها قبل أن تَعِد المتدرّب بشيء

| العمل | مَن ينفّذه |
|---|---|
| `claude mcp add …` | **أنت** (عبر سطر الأوامر) |
| `claude mcp list` للتحقّق | **أنت** |
| كتابة المفاتيح في `.env` | **أنت** |
| إنشاء الحسابات ونسخ المفاتيح | المتدرّب |
| `/mcp` ← **Authenticate** ← الموافقة في المتصفّح | **المتدرّب وحده** — تدفّق تفاعلي يحتاج هويّته، ولا تستطيع أنت تنفيذه |

> **تنبيه لازم أن تقوله للمتدرّب:** الخادم المضاف حديثًا **لا يعمل في الجلسة الحالية**؛ لا بدّ من **إعادة تشغيل Claude Code** أو إعادة الاتصال عبر `/mcp`. إن لم تقل هذا، سيظنّ المتدرّب أن الربط فشل.

## 2. context7

**لماذا؟** يجلب توثيق المكتبات والأطر المحدّث فتكتب كودًا مطابقًا لأحدث الإصدارات. **يُربط قبل أي عمل برمجي** — أي قبل تهيئة التطبيق في اليوم الأول.

**ما يفعله المتدرّب:** ينشئ حسابًا على <https://context7.com/> ← لوحة التحكّم ← **API Keys** ← ينشئ مفتاحًا وينسخه (يبدأ بـ `ctx7sk-`) ← **يلصقه لك في المحادثة**.

**ما تفعله أنت** بعد أن يعطيك المفتاح:

```
claude mcp add --scope user --header "Authorization: Bearer <KEY>" --transport http context7 https://mcp.context7.com/mcp
```

- `--scope user` مقصود: التوثيق المحدّث نافع في كل مشاريع المتدرّب لا في مشروع الدورة وحده.
- على PowerShell أبقِ قيمة `--header` بين علامتَي اقتباس مزدوجتين كما هي أعلاه.
- الاتصال البعيد يعمل **بلا مفتاح** لكن بحدّ استخدام منخفض (anonymous rate limit)؛ ولهذا نستخدم مفتاحًا.

**بعدها:** أخبر المتدرّب أن يعيد تشغيل Claude Code، ثم تحقّق أنت بـ `claude mcp list` من ظهور `context7 … ✔ Connected`.

## 3. إنشاء مشروع Supabase — **قبل** ربط الـMCP

**الحسابات متطلّب مسبق** (GitHub · Supabase · منصّة النشر · بريد فعّال) يجهّزها المتدرّب قبل الدورة. أمّا **مشروع** Supabase فيُنشأ الآن، **ولا بدّ منه قبل الخطوة التالية** لأن الـMCP يحتاج مشروعًا يشير إليه.

وجّه المتدرّب في <https://supabase.com/dashboard> ← **New project**:

| الحقل | ما تقوله له |
|---|---|
| **Organization** | مؤسّسته الشخصية (تُنشأ تلقائيًّا مع الحساب) |
| **Project name** | اسم منتجه — حروف صغيرة وشرطات |
| **Database password** | ⚠ **انسخها واحفظها الآن في مكان آمن** — لا تُعرض مرّة أخرى، واستعادتها تتطلّب إعادة تعيين |
| **Region** | الأقرب جغرافيًّا لمستخدميه (يقلّل البطء) |
| **Plan** | **Free** يكفي للدورة بالكامل |

التجهيز يستغرق دقيقة أو دقيقتين. بعده تجد بيانات الاتصال في **Project Settings**: نصّ الاتصال بقاعدة البيانات (connection string)، ورابط الـAPI ومفاتيحه (publishable keys).

**اطلب منه أن يلصق لك ما يلزم، واكتبه أنت في `.env`** — لا يفتح هو الملف. وتأكّد أن `.env` في `.gitignore`.

> **لماذا Supabase؟** تعطي قاعدة بيانات **ونظام تسجيل دخول جاهزًا** معًا، بلا Docker وبلا تثبيت محلّي، وتعمل نفسها في التطوير وبعد النشر — فلا فرق بين البيئتين.

## 4. Supabase MCP

**لماذا؟** يتيح لك إنشاء الجداول وتشغيل التهيئة وقراءة سجلّات قاعدة البيانات مباشرةً — فلا يحتاج المتدرّب أن يفتح لوحة Supabase ويكتب SQL بنفسه.

**ما يفعله المتدرّب في لوحة Supabase:** يفتح مشروعه ← زر **Connect** ← تبويب **MCP** ← يختار العميل **Claude Code** ← يترك **read-only** **مُطفأً** (لأنك ستُنشئ الجداول نيابةً عنه) ← يترك مجموعة **Storage** مُطفأة (لا نحتاجها) ← ينسخ معرّف المشروع (project ref) إن ظهر له.

**ما تفعله أنت:**

```
claude mcp add --scope project --transport http supabase "https://mcp.supabase.com/mcp"
```

- `--scope project` مقصود: قاعدة البيانات تخصّ هذا المشروع وحده، فلا تُسرّبها إلى بقيّة مشاريع المتدرّب.
- إن أعطاك المتدرّب معرّف المشروع، اربطه بمشروعه تحديدًا: `"https://mcp.supabase.com/mcp?project_ref=<REF>"` — وهذا أفضل، إذ يمنع وصولك إلى بقيّة مشاريعه.
- لا يحتاج هذا التكامل مفتاحًا شخصيًّا (Personal Access Token)؛ التوثيق يتمّ عبر OAuth في المتصفّح.

**ثم — خطوة المتدرّب وحده:** يشغّل `/mcp` ← يختار `supabase` ← **Authenticate** ← يوافق في المتصفّح. اشرح له ما يمنحه من صلاحيات قبل أن يوافق.

**التحقّق:** اطلب منه أن يسألك عن جداول قاعدته، ونفّذ الطلب فعلًا لتثبت أن الربط يعمل.

## 5. التكاملان المؤجَّلان — لا تربطهما في اليوم الأول

نوزّع مجهود التهيئة على الأيام بدل تكديسه في اليوم الأول:

- **chrome-devtools** — يُربط في القسم **14.2** مع بدء البناء والاختبار (تحتاجه لتجربة المنتج في المتصفّح كما يفعل المستخدم).
- **Vercel MCP** — يُربط في القسم **16.2** مع النشر. تفاصيله في مهارة `deploying`.

إن طلب المتدرّب ربطهما مبكرًا فلا مانع، لكن نبّهه أن كل تكامل مربوط **يزيد حجم كل رسالة** ويستهلك رصيده (القسم 7.6).

## 6. أمان المفاتيح — قاعدة صارمة

عندما يلصق المتدرّب مفتاحًا في المحادثة:

- استخدمه في الأمر أو اكتبه في `.env` **فقط**.
- **لا تُعِد كتابته في ردّك**، ولا تضعه في `conversation_history.md` ولا في `PRODUCT.md`. عند توثيق الخطوة في سجلّ المحادثة اكتب `<تم استلام المفتاح>` بدل قيمته.
- تأكّد أن `.env` مذكور في `.gitignore` قبل أول رفع.
