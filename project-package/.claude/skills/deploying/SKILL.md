# النشر على Vercel

دليل التنفيذ الخاص بك أنت (Claude). خطوات المتدرّب في القسم **16** من ملف خارطة الطريق.

**أنت تقود النشر؛ والمتدرّب يؤكّد الدخول في المتصفّح فقط.**

## 1. تقسيم الأداتين

| الأداة | مسؤوليتها |
|---|---|
| **Vercel MCP** (`https://mcp.vercel.com`) | إدارة المشروع والنشر، **قراءة سجلّات النشر**، تشخيص الأعطال، البحث في التوثيق |
| **سطر الأوامر (CLI)** | النشر الفعلي **وضبط مفاتيح البيئة** — الـMCP لا يملك أدوات لمتغيّرات البيئة بعد |

استخدمهما معًا؛ لا يغني أحدهما عن الآخر.

## 2. الترتيب

**أ) المتطلّب المسبق — ربط Vercel MCP (مرّة واحدة، قبل النشر):**

```
claude mcp add --transport http vercel https://mcp.vercel.com
```

ثم يشغّل المتدرّب `/mcp` ويؤكّد الربط في المتصفّح (OAuth). Claude Code عميل مدعوم رسميًّا. بهذا تقرأ سجلّات النشر وتشخّص الأعطال **بدل التخمين**.

**ب) تسجيل الدخول (خطوة المتدرّب):** شغّل `vercel login` — يظهر رابط/رمز تأكيد **يكمله المتدرّب في متصفّحه**؛ لا تستطيع أنت ذلك لأنه يحتاج هويّته. بهذه الخطوة يمنحك صلاحية النشر على حسابه.

**ج) الربط والنشر (تقودها أنت):**

1. `vercel link` — يُنشئ مجلّد `.vercel`؛ **تأكّد أنه في `.gitignore`** قبل أي رفع.
2. اضبط **مجلّد الجذر (Root Directory)** على مجلّد التطبيق (`app/`).
3. أضِف **مفاتيح الإنتاج**: `vercel env add <NAME> production` — اتصال قاعدة البيانات وأي خدمة خارجية.
4. `vercel --prod`
5. سلّم **الرابط الفعلي** للمتدرّب.

**د) بعد النشر:** حدِّث روابط أي خدمة خارجية (رابط عودة OAuth، والسماح بالمصدر CORS إن وُجد خادم منفصل) لتشير إلى رابط الإنتاج الجديد.

## 3. العقبات الخمس — تجنّبها استباقيًّا

هذه أعطال وقعت فعلًا في تجربة حقيقية:

1. **الوقوف في لوحة Vercel بلا خطوة تالية واضحة** ← قُد أنت الخطوات ولا تترك المتدرّب يبحث.
2. **فشل `vercel whoami`** لأن الأداة غير مسجّلة الدخول ← `vercel login` أولًا.
3. **نسيان ضبط مجلّد الجذر أو إضافة المفاتيح قبل النشر** ← يُنشر المنتج ثم ينكسر عند التشغيل.
4. **نسيان تحديث روابط الخدمات الخارجية** بعد معرفة رابط الإنتاج.
5. **رفع `.vercel` إلى GitHub بالخطأ** ← يبقى في `.gitignore` دائمًا.

## 4. حين يفشل النشر

**لا تخمّن.** اقرأ سجلّ النشر عبر Vercel MCP، ثم بلّغ المتدرّب بلغة بسيطة: ما الذي فشل، ولماذا، وما الذي ستفعله لإصلاحه. ثم أصلِح وأعد النشر.

## 5. إعادة النشر لاحقًا رخيصة

بعد أول نشر ناجح تصير خطوات الإنتاج جاهزة، وكل نشر لاحق هو `vercel --prod` فقط (بعد رفع التعديلات). قُل هذا للمتدرّب صراحةً كي لا يخشى إعادة النشر.

## 6. أمان المفاتيح

مفاتيح الإنتاج تُضاف عبر `vercel env add` أو تُكتب في `.env` — **ولا تُعاد كتابتها في المحادثة**، ولا تُوضع في `conversation_history.md` ولا `PRODUCT.md`.

## 7. أين تُكتب النتيجة

الرابط الفعلي وخطوات النشر تُكتب في **`PRODUCT.md` القسم 9 «النشر»**، وتُضاف Vercel وVercel MCP إلى جدول الأدوات (القسم 10). ثم حدِّث سجلّ التقدّم في `CLAUDE.md`.
